# Harvy V2 Master Plan

This is the single project plan. It supersedes older plans and implementation notes; verified behavior must be separated from proposals.

## Canonical layout

- V2 source, Workers, connectors, migrations, and Wrangler configs live under root `v2/`.
- Do not create or document a duplicate root tree. V2 source lives only under `v2/`.
- Keep existing Cloudflare resource identifiers unchanged unless a separately reviewed migration requires a rename.
- Repository docs and notebooks are canonical; mirrors are generated by the documented sync commands.

## Verified status (2026-10-27)

- The supervisor and JudyRecords/Truth Social Workers were deployed and exercised with bounded samples. Truth Social produced one profile artifact; a supplied JudyRecords record URL produced a raw HTML sidecar and normalized JSON. These samples do not prove full history or search coverage.
- JudyRecords term discovery and pagination are not verified; the generic search crawl found no record links. Do not start a 75,000-record run until distinct-record validation, parser coverage, retries, and run accounting pass a bounded test.
- Truth Social timeline pagination and historical completeness are unverified. Collect only public content; do not use logged-in cookies.
- SAM.gov connector code exists, but it is not bound to the supervisor and has no verified live sample.
- CourtListener bulk import is not implemented. Port targeted search into V2 before claiming that capability is available.
- No remote Workers, queues, VPS processes, or stored data were changed by the V2 conversion; reconcile any still-running external consumers separately before decommissioning them.
- Better Auth source and D1 migrations are under `v2/auth/` and `v2/migrations/`. The auth Worker now targets the shared V2 D1 database; no migration or deployment was performed by this refactor.
- Shared canonical ontology and dashboard schema is defined by `v2/migrations/0006_ontology_and_dashboards.sql`; it has not been applied remotely.
- `harvy-raw` stores raw captures, `harvy-artifacts` stores normalized records, and Basin is the separate analytics path. The configured `harvy-platform-v2` D1 name is a remote resource identifier, not a filesystem path.
- The 75% cache-hit target applies only to eligible public responses and has not been measured on a representative workload.

## Contradiction audit

- V2 implementations and configs are under `v2/`. Do not document a second root or a root Worker.
- Active configs bind `harvy-raw` / `harvy-artifacts`. Do not rename live buckets.
- Auth migrations live under `v2/migrations/`. The V2 auth config targets the shared V2 D1 database.
- The V2 supervisor does not currently provide query endpoints; the UI must not be represented as working until the V2 route is implemented and tested.
- Facebook and CourtListener functionality has no complete V2 equivalent. Those ports are explicit work items above, not capabilities to assume from the catalog.

## Operating constraints

- Use Spider Unlimited by default; do not switch to metered endpoints without explicit authorization. Serialize AI Studio calls to the account limit and bound each run.
- Keep credentials in environment variables or Cloudflare Secrets Store. Never put secret values in source, docs, notebooks, logs, or command arguments.
- D1 is operational/index data, R2 retains raw and normalized artifacts, and Basin handles historical analytics. Preserve attribution and evidence; a name match is not a verified identity.
- Reconcile any VPS or other external consumer before changing its remote queue or service; preserve queued work and do not delete remote resources as part of local cleanup.
- Do not deploy, run remote migrations, or alter provider settings without explicit authorization. A local test or health response is not proof of collection completeness.
